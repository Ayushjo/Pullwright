## Synthesis — what the best 50 have in common

**Hero structure (three dominant archetypes)**
1. **The product window over art** (Devin, Cursor, Warrn, Linear, Graphite): left-aligned 2-line headline, one-line subhead, a dark pill + ghost CTA pair, then the *real app* framed over a painted/photo/blueprint backdrop. This is the category standard for coding agents. We already do a version of it (ProductShot sky backdrop).
2. **The input is the hero** (Motion, Designspo, Factory's command chip, our own issue box): a prompt/search box front and centre, with example chips under it that fill the input on click. Strongest conversion pattern when the product starts from one paste.
3. **Mood/type-led** (Resend, Raycast, Omnisavant, Empowrd, Deskmodes): one huge headline, often **serif**, over a single striking visual (3D object, light streaks, glow). Memorable but says less.

**Typography**
- Headlines are 48–72px on desktop for products (bigger only on mood sites), weight 500–600 rather than 700+, tight tracking.
- **Two-tone headlines** (second line dimmed or coloured) appear on hinge, deskmodes, wemakedevs, linear — we already use this; it's current.
- **Serif accents** are the fashionable move this year: Resend, Motion, Warrn, Parvu, Empowrd. Usually one italic serif word inside a sans headline, or a serif display face for the whole H1.
- **Mono eyebrows/labels** are everywhere in dev tools (Clarc, Hinge, CodeRabbit, WeMakeDevs, Factory). Ours matches.

**Trust and specificity**
- A **spec line under the CTA** (Graphite "No credit card required. Sign up with GitHub.", Hinge, Raycast). Ours exists; keep it short and factual.
- **Real numbers** (posts.design "860+ brands", "32 joined today"; WeMakeDevs stats boxes). We have real eval numbers (34/40 solved, ~$0.016 a task on Haiku) — honest numbers beat logos we don't have.
- **Numbered steps as panels with real UI crops** (CodeRabbit 01–04) explain an agent pipeline better than icons.
- **Example chips** of task types (Jules: Bug fixing / Version bumps / Tests) make "what can it do" concrete in one glance.

**Things to avoid**
- Gated-content modals on first visit (ogfolio), fake logo walls, autoplay video soup (collectui), all-caps everything.
- Light-weight display type on busy gradients loses legibility (uselayouts).

## What to try on Pullwright
- Keep the issue box as the hero action; add **example-issue chips** under it ("Fix a failing test", "Bump a dependency", "Add input validation") that fill the box with a real public demo issue.
- A **serif accent word** in the H1 (e.g. "Reviewed *pull request* out.") — the single most current, cheapest upgrade.
- Replace any vague claim with **eval numbers** in a quiet stats row.
- A **numbered pipeline** (01 Plan → 02 Code in sandbox → 03 Tests → 04 Independent review → 05 You approve) with real UI crops, CodeRabbit-style.
- One dark variant to compare against the current light one (Devin/Cursor are light-warm; CodeRabbit/Graphite/Linear dark).
